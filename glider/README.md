# glider — wireframe hovercraft raid (working title)

The game this workspace is building toward: a first-person raid over a
flat, entirely artificial world, flown in a fragile hover-glider with
tank controls and drift. Starglider 1 is the look, and Battlezone
supplies a few ideas. It runs in mode 4 with the machine fully taken
over, double-buffered at the VBL. The design, budgets and milestones
are in [docs/engine-spec.md](../docs/engine-spec.md).

**Status:** M1 (flight rig) and M2 (world: entities, culling, clipping,
per-object erase) are done, so you can fly around a static test map of
towers, blocks and mines. M3 comes next: the top strip with the radar,
then combat.

## Build and run

```
make          # check the register contracts, assemble, package glider.qlpak
make run      # launch Q-emuLator (close it before rebuilding)
make mdv      # glider.mdv, a Microdrive image for real hardware and FPGA cores
make runmdv   # boot the .mdv in Q-emuLator
make check    # the register-contract check alone
```

The toolchain is described in the [root README](../README.md). On the
MiSTer QL core the wireframes flicker; that's a core bug, see
[docs/mister-flip-latch-issue.md](../docs/mister-flip-latch-issue.md).

## Controls and screen

Arrows: Left/Right turn, Up thrusts, Down brakes, and holding Down at a
standstill engages reverse. Enter puts the craft back at the spawn
point.

The band at the bottom shows speed and drift (tenths of a unit per
beat), heading and the number of objects drawn. The second group of
readouts and the bar along the bottom edge are performance meters
measuring idle time per frame; `hud.asm` explains each field.

## Where things are

`glider.asm` is the only file vasm is given. It includes the rest, and
the include order is the memory layout.

| File | Contents |
|---|---|
| `glider.asm` | file map, job header, takeover, the frame loop |
| `equates.inc` | hardware addresses, the tuning knobs, record layouts |
| `flight.asm` | flight model (one step per 20 ms beat), craft reset |
| `lattice.asm` | the ground-dot stage (wedge scan, table projection) |
| `objects.asm` | the object stage: cull, transform, clip, draw, erase boxes |
| `render.asm` | the erase stages, projection, clipping, list helpers |
| `hud.asm` | readouts, meters, headroom bar |
| `strip.asm` | the sight and the top strip's radar |
| `macros.inc`, `vars.inc`, `level.inc` | loop macros, variables, the test map |
| `meshes.inc`, `sin.inc` | generated by `tools/genmesh.py --game` and `tools/gensin.py` |

The line drawers, the decimal readout and the IPC keyboard and sound
routines come from [`lib/`](../lib). Every routine carries a register
contract that `tools/regcheck.py` checks on each build; the rules and
the project's other conventions are in [CLAUDE.md](../CLAUDE.md).
